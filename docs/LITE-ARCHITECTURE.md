# Lite 数据与交互约定

## 业务对象

`tasks(id, title, status, created_at, parent_id, unread_completion)`：任务唯一编号即自增主键。状态只接受 `todo / doing / done`，由用户修改。

`sessions(id, task_id, title, status, updated_at, bound_at)`：Codex 会话 UUID 是主键。一个会话最多绑定一个任务，一个任务允许多个会话。`task_id` 允许为空，解除或删除后的会话用 `bound_at` 阻止旧指令覆盖用户操作。没有项目、空间、分支、Run、流水线、通知、设置表。

- `parent_id` 为空即主任务，否则只能指向主任务；数据库外键和触发器限制为一层。快照按主任务及其子任务分组，父子状态与会话关联独立。删除父任务时 `ON DELETE SET NULL` 保留子任务，移到最外层。
- schema 1 → 2 → 3 在写事务内增量增加父关系、索引、层级触发器和完成未读标记，不重建库，不修改旧任务或会话。旧版 Lite 程序不支持 schema 3。
- schema 5 → 6 增加 `manual_ordering(scope)` 排序偏好表：`tasks:0` 为主任务，`tasks:<父任务ID>` 为子列表，`sessions:<任务ID>` 为关联会话。默认任务按 `created_at DESC,id DESC`；会话按 `updated_at DESC,bound_at DESC,id DESC`。有效拖动以当前可见排序为基准写入完整同级 `sort_order` 并记录手动模式；无效或位置未变的拖动不切换模式。手动模式沿用新增追加末尾，刷新与重启保留。旧库没有拖动标记，迁移时与旧追加顺序（任务 ID 升序／会话绑定时间及 ID 升序）比较，有差异的组保留手动顺序，其余采用默认倒序；历史操作恰好恢复旧默认顺序时无法区分。
- schema 6 → 7 增加 `sessions.activity_order`：默认等于最后活跃时间，手动列表升级时为 0 以保留旧顺序。有效 session 拖动会固化当前所有卡片的 `sort_order`，同时将其 `activity_order` 清零；只有严格更新的活跃记录（或新关联）重新写入活跃时间，优先按该时间倒序，再按手动顺序。因此拖到底部的会话后续活跃仍会置顶；重复轮询、相同或更旧的记录不提升优先级。任务的手动排序规则保持不变。最后活跃时间取 Codex 索引与已解析 `event_msg`／`response_item` 日志时间的最大值，Hooks 合并继续采用事件时间；不用轮询时间或文件 mtime。
- SQLite WAL + FULL；写操作使用 `BEGIN IMMEDIATE`，快照读取在一个事务内完成。
- 数据库使用独立 `application_id` 与 `user_version`。旧版、未知或未来 schema 均拒绝覆盖。
- `unread_completion` 仅在已关联且归属不变的会话由 running → completed 时置位，更新和会话状态写入同一事务。过时状态不覆盖较新状态；历史已完成会话初次关联不提醒。点击任务显式清除；重复完成观察不重新置位。
- 侧栏宽度和折叠任务 ID 存 UserDefaults；隔离验收使用独立偏好。折叠父任务汇总子任务未读，不替子任务清除；创建子任务自动展开父任务。
- 自动关联要求：用户消息独立行、任务存在、指令不早于任务创建、指令晚于最后绑定／解除时间。
- 同一任务再次关联其它会话时只新增该会话，不替换已有会话。
- 切换任务的人工状态不会更改任何会话的运行状态，反之亦然。
- 删除任务保留会话解绑时间；不修改 Codex 数据。

## 模块

- `LiteCore/TaskStore.swift`：唯一的本地任务数据写入入口。
- `LiteCore/CodexReader.swift`：只读全部本机会话元数据和受限路径内的日志，后台增量解析。
- `FloatingWorkbench/AppModel.swift`：异步刷新、选择和用户动作。
- `FloatingWorkbench/Views.swift`：单屏任务列表、详情、会话卡片和快速记录。
- `FloatingWorkbench/TaskSplitView.swift`：原生分栏托管，大小形态共用左右托管视图，动画时保持侧栏宽度并裁剪详情，内容变化和弹窗关闭不重置宽度。
- `LiteCore/WindowShortcut.swift`、`FloatingWorkbench/ShortcutRecorder.swift`：快捷键配置与校验、原生录制按钮及 Carbon／菜单按键映射。
- `FloatingWorkbench/AppHost.swift`：任务窗口、独立设置窗口、菜单栏、快捷键和隔离窗口验收。
- `FloatingWorkbench/CodexMonitor.swift`：观察 Codex 索引、日志和本地 Hooks 事件；不观察 SQLite SHM，避免读取反馈循环。

## 界面

参考草图只表达布局，视觉沿用 v1-full 的原有风格：浅灰侧栏、蓝色强调色、深色文字、圆角白色卡片和淡色状态标签。不得将草图红线当成视觉规范。主体只有两栏，原生分隔线可拖动，首次左宽 300，重启恢复上次宽度。正常形态的底部输入框横跨两栏，仅通过回车新建；小窗口隐藏该输入栏，草稿继续保留。

左侧隐藏任务编号，卡片全部留白区域可点击切换，状态圈与折叠箭头单独响应；子任务缩进一层。父任务右侧箭头折叠／展开，卡片右侧的状态位在有关联会话运行时显示蓝色旋转小圈，运行结束后恢复完成未读红点。运行状态汇总自身及所有子任务，不受子任务折叠或筛选影响；多个会话中只要还有运行中的会话就优先转圈。完成红点仍按原有已读规则处理，父任务仅在折叠时汇总子任务未读。左侧标题最多三行并提供全文悬停提示。详情任务编号紧挨任务名；原圆形加号的位置放“＋ 子任务”。第二行状态组在左，删除图标与“关联会话”在右，关联按钮最右对齐。会话弹窗支持连续多选，点击外部收起；“创建新会话”通过 `codex://threads/new?prompt=...` 打开包含关联指令和末尾换行的新草稿，不自动发送。


窗口使用透明原生标题栏，交通灯与自定义标题、单个 `>`／`<` 方向箭头同排。保持一个 RootView 和任务列表，收起时隐藏右侧详情和快速创建，原生窗口宽高同时动画缩放为正方形，边长等于实际左栏宽度；展开时恢复正常宽高及快速创建。固定左上角，屏幕空间不足时避让；小窗口调整大小时约束为正方形，不覆盖记住的正常窗口尺寸。点击任务仅选择，折叠与完成按钮不切换形态；右上角按钮控制详情，默认 `⌘⇧空格` 循环隐藏 → 小窗口 → 正常窗口 → 隐藏。系统开启“减少动态效果”时直接切换。设置中录制并保存快捷键，录制期间暂停本应用快捷键，取消／结束恢复；注册新组合成功后才替换旧组合，失败保留旧配置；旧设置文件缺失该字段时采用默认值。

没有原版模块、顶部 Tabs、工作空间入口、服务运行状态、同步按钮或外部执行调度。连接设置独立从 macOS 菜单打开，不占用任务主体布局。

## 可选连接与 Hooks

- `IntegrationSettings`：当前用户的 Codex 目录、应用位置及读取间隔；独立 JSON 不增加业务表。
- `HookInstaller`：合并配置、备份、稳定路径部署及仅移除本应用 Hooks；不更改 Codex 信任记录。
- `CodexTasksHook`：双架构原生命令，接收 stdin，仅写入本地元数据事件；任何解析错误均静默成功退出。
- `HookEventStore`：每会话锁、原子写、乱序过滤；与索引观察按时间合并，最终仍通过 TaskStore 统一协调关联与完成提醒。
- 保存设置会使旧后台读取失效，避免更换连接后旧回调写入过时关联。

详细路径审计、配置边界与迁移说明见 `CONFIGURATION.md` 及 README。
