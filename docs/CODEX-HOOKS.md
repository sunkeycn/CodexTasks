# Codex 生命周期状态上报

## 当前链路（1.4.1）

主路径为 **异步 command hook → 原生 CodexStatusHook → 本机 HTTP → 单会话同步 → 界面**。原生助手随应用打包，不需要启动 Python。`scripts/codex-status-hook.py` 保留为源码调试与兼容入口。

助手先将必要元数据原子保存到 `~/.codex/codex-tasks-status/<会话ID的SHA256>.json`，再通过 HTTP 上报。同轮次已经记录完成或中断时，晚到的开始事件不会覆盖终态。写入者按会话加锁；原生助手等待锁及 HTTP 都有短时限，任何上报错误不改变 Codex 操作结果。

| Hook | 工作台状态 |
| --- | --- |
| UserPromptSubmit | 正在运行 |
| Stop | 运行完成（不代表人工任务完成，也不证明业务或测试成功） |
| Interrupt | 执行中断 |

只保存版本、会话 ID、轮次 ID、工作目录、事件名和时间，不保存提示词、回复或工具内容。等待审批、等待输入、进程崩溃尚无完整状态映射；开始后超过 3 分钟没有新证据时仍保守显示同步未知。

## 本机 HTTP

应用启动时绑定 `127.0.0.1` 的随机端口，仅提供 `POST /v1/events`。发现信息在 `~/.codex/codex-tasks-bridge/endpoint.json`，目录权限 0700，文件权限 0600；其中的随机认证凭据只用于本机请求，不要复制到聊天、截图或日志。应用正常停止时删除属于自身的发现文件，下次启动更换端口和凭据。

请求需携带 Bearer 认证，头部最多 4 KiB，正文最多 16 KiB，连接有超时和数量上限。202 表示事件已经受理排队，不代表任务完成或关联成功。

接收端通过本机索引按会话 ID 定向读取，不遍历全部会话；校验当前工作区、cwd、轮次和时间后，调用原有 WorkbenchService 写入口。未知会话不会创建任务或建立关联；索引稍晚出现时做有限重试。任务关联仍来自用户的独立行指令或已有显式绑定。终态保护、工作区隔离和人工完成状态规则保持有效。

## 文件恢复与其它通知

- FSEvents 现在传递具体变化路径。已知日志和状态文件按对应会话读取，合并窗口为 50 ms；索引和 WAL 变化仍做发现同步，窗口为 300 ms。
- HTTP 事件会优先于尚未开始的发现扫描。索引发现稍后补做，避免一次 HTTP 上报被扩大成全量扫描。
- 启动、切换工作区、重新激活、唤醒、手动同步及 60 秒兜底仍能恢复状态；大日志仍优先读取最新尾部，再分段补历史。定向补历史不循环扫描其它会话。
- CodexTaskRunner 每次保存回执后立即发 HTTP 通知。接收端只接受当前工作区已登记的回执路径。2 秒回执定时器仅作兜底；新会话仍通过独立 CLI 执行并由深链接打开。
- Git 在独立队列检查。无语义变化时不发布界面通知，后台 I/O 不驱动编辑页重绘，不监听 SQLite SHM。

## 安装与信任

构建后可运行：

```sh
python3 scripts/install-codex-hooks.py
```

安装器将三个异步生命周期处理器合并到 `~/.codex/hooks.json`，保留其它 Hooks；重复执行不会重复添加自己的处理器。命令引用固定输出应用中的原生助手。也可在应用设置中复制 Hooks 配置自行合并，或将配置放进选定项目的 `.codex/hooks.json`。

**安装配置与 Codex 的信任审核是两个步骤。** Codex 默认会审查命令 Hooks；首次启用或命令改变后，需要在其 Hooks 管理界面审核，CLI 可用 `/hooks`。安装器和应用都不会替用户写入“已信任”状态或关闭审核。当前会话和运行模式是否触发回调，以真实事件为准；文件兜底始终可用。

源码 Python 配置生成器：`python3 scripts/codex-status-hook.py --print-config`。移动应用后需重新安装或生成配置。调试可用 `--status-directory` 和 `--endpoint-file` 指向隔离目录，两种助手均支持。

## 验证范围

核心验收覆盖 HTTP 鉴权、大小限制、协议拒绝、端点清理、Python 与原生助手到定向 reader/服务的链路、乱序终态保护、索引与工作区校验、无服务时文件恢复。原生窗口验收使用隔离 Codex 索引、任务数据库、HTTP 端点和实际打包助手，验证 Hook 到 AppModel 状态更新及耗时，不启动真实 Codex 任务。
