# CI/CD 交互设计 · 评审稿

日期：2026-11-02。状态：用户已确认并进入实现；实现与验证边界见 `CICD-IMPLEMENTATION.md`。下文保留设计阶段的调研记录。

本轮仅检查本机 CLI 帮助、当前应用源码及云效公开官方文档；未读取账号凭据、查询组织内流水线、安装插件或执行流水线。原生应用未修改，无需重新打包。预览中的组织、项目、流水线、实例、资源与日志均为示例。

## 1. 设计结论

沿用 Codex Tasks 的任务 / 项目 / CI/CD 导航。CI/CD 从当前的模拟部署表单，改成「流水线目录 + 详情侧栏」。日常路径是：

**我的关注 / 全部流水线 → 选择流水线 → 查看详情或运行 → 选择代码源、变量、制品 → 核对实际范围 → 提交 → 跟踪运行。**

- 全部流水线：当前账号在当前云效组织有权限看到的全部 Flow，完整分页，不代表组织管理员可见的所有资源。
- 我的关注：首版本地关注，按站点、组织、账号、pipelineId 隔离；明确显示“本地关注”。未确认公开 API 能同步云效网页收藏，不虚构同步能力。
- 项目关联：优先匹配代码源与已有项目的 Git remote；有歧义时展示候选并人工确认。
- 环境关联：以部署配置和用户确认的映射为依据；名称、标签、envId 仅提供线索。一个 Flow 可以有多个项目、多个环境。
- 执行参数：依据实际流水线生成表单，不再只有一个自由文本参数框。配置无法解析时可补充本地参数定义；补配不修改远端流水线。
- 授权：界面提供浏览器 OAuth 与 PAT 两种路径。OAuth 是云效开放能力支持的协议，不代表 CLI 已自带 OAuth 登录命令。

## 3. 主界面

### 页面结构

- 保留左侧原有工作区及三个导航入口。
- 页头：CI/CD、站点/组织、连接状态、最后同步时间、刷新、连接设置。
- 标签：**我的关注（本地） / 全部流水线**。初次进入显示全部；有关注后记住上次选择。
- 筛选：流水线名称或 ID、项目、环境、最近状态；“未关联”作为项目和环境的显式选项。
- 全部视图默认跨当前云效组织展示；切换工作区不会把未关联 Flow 悄悄过滤掉。项目筛选只引用工作台已有且授权可访问的项目。
- 列表列：关注、名称/ID、关联项目、环境、最近运行、操作。
- 最近运行要显示实例状态、分支或 Tag、运行时间；“从未运行”“尚未加载”“同步失败”是不同状态。
- 多项目显示主要项目 + 数量；多环境显示“运行时选择”。详情列出完整范围。
- 点击名称打开详情侧栏；点击运行直接进入该 Flow 的参数页。窄窗时侧栏切换为内容页，提供“返回流水线”。

### 关注行为

星标点击即时更新本地状态，列表数量同步变化。取消关注不会删除流水线或运行历史。关注按稳定 ID 保存，重命名不丢失。失去权限后保留不可用条目并解释原因，不能把一次网络失败当成删除。

如果用户已有网页收藏，首版支持按流水线 ID/名称检索后批量加入本地关注；必须明确这是迁移选择，并非双向同步。以后若获得官方关注 API，再独立设计远端同步与冲突处理。

### 详情侧栏

顶部名称、ID、最近状态；展示「概览 / 运行记录 / 关联配置」。概览含代码源、部署目标、关联依据和最近执行阶段。运行记录按实例展示，选中后显示阶段/任务、触发人、分支/Tag、开始时间、耗时、备注和日志入口。保留“在云效打开”，链接使用校验过的真实站点与实例定位方式。

本轮原型只演示列表、概览、参数、配置、确认及提交后的运行状态；完整日志检索与批量操作属于后续实现。

## 4. 正确关联项目与环境

### 项目匹配

匹配优先级：

1. 用户已确认的 pipelineId + sourceId → 本地 projectId 映射。
2. 云效代码源的 repo 与已有项目 remote 的精确匹配。归一化 SSH/HTTPS 表达、末尾 `.git` 与斜杠；保留仓库路径大小写；不同域名仅允许显式配置的别名。
3. 名称、标签等仅形成候选，不自动确认。

同仓库多个本地克隆、一个 Flow 多仓库、monorepo 多子项目都需要保留多对多关系。无法唯一定位时提示“请选择本地项目”；没有本地项目时允许保留远端仓库记录，不为了关联而扫描其他 namespace。

自动找到唯一仓库可标“仓库匹配”；首次运行前仍要求确认部署项目和资源。人工配置优先于自动建议。云效配置更新后检测绑定是否还成立，发生冲突标记“需重新核对”，不覆盖用户映射。

### 环境配置

每个 Flow 支持三种模式：

- **固定环境**：如 test。展示来源与资源清单；如果 Flow 实际需要变量，也配置该变量与值，不能只有界面标签。
- **运行时选择**：绑定真实变量键（示例 DEPLOY_ENV）及枚举映射。用户选择 eu 时，执行参数与确认范围同时切换至 eu 对应资源。
- **不涉及部署**：仅适用于已核对流程/脚本用途的纯 CI；是影响类型，不是一个可绕过生产校验的环境别名。

每条映射包含：环境原名、实际运行值、项目、部署资源（主机组/集群/命名空间/应用/服务）、动作、影响面、证据来源、确认时间、对应流水线配置版本。

envId=0 不自动等于 test，envId=1 不自动等于 pre；“正式环境”也不自动等于 eu。branch、名称或用户选中的本地环境不会改变远端 Flow 的部署行为。

混合流水线可能一次部署多个环境，确认页必须列出全部目标，按最高风险处理，不能用一个下拉项隐藏其他部署阶段。

除 dev/test/daily/pre 外全部按生产；未知环境按生产处理，但缺少实际目标时先阻止执行并要求补配。用户不能把 eu/sea/publish 等重命名成 test 来降低实际目标的风险等级。

### 配置界面

点击“配置关联”打开侧栏，依次填写代码源项目、环境模式、真实变量键和值映射、资源、动作和影响面。显示“识别依据”和冲突位置。保存只更新工作台本地绑定，不更新云效流水线。

本地表单定义可补充 label、变量键、字符串/枚举/私密、选项、默认值、必填、用途和来源；枚举提交真实 value，显示 label。元数据失效时提示重新检查，不悄悄退化成任意 JSON。

## 5. 运行配置

按云效网页的运行配置组织内容，并扩展项目与环境核对。

1. **基本信息**：Flow、项目、环境；固定环境只读，动态环境选择必须绑定实际运行变量。
2. **代码源**：每个源独立选择分支 / Tag，展示仓库；可以检索，权限不足时保留手动输入并标注未验证。默认使用云效配置值；从任务进入可提示任务分支，用户主动采用。
3. **运行变量**：只将配置允许的运行变量设为可编辑；字符串为输入框，枚举为单选，私密为密码框。标注默认值、来源、必填和允许覆盖状态。保留服务端默认值与提交空字符串是不同动作。
4. **制品**：存在制品源时才展示上游流水线实例、镜像版本或 Packages 版本；分别映射 runningPipelineArtifacts / runningAcrArtifacts / runningPackagesArtifacts。无查询权限时可输入已知版本并明确验证状态，不编造候选。
5. **备注与任务关联**：comment 可编辑；任务可选。运行结果不能把任务的人工完成状态自动改掉。
6. **核对执行范围**：先刷新定义、目标和可解析的版本，再生成不可变预览。变化时使旧确认失效。

特殊情况：branchModeBranchs 是分支模式的独立能力，不与多代码源选择混为一谈。首版识别到不支持的分支模式或不明配置时引导到云效网页，并说明无法在本应用完成；禁止静默丢弃参数。阶段选择/跳过只有在对应公开契约明确支持时才开放。

### 提交映射

| UI 内容 | CreatePipelineRun.params |
| --- | --- |
| 单个/多个仓库分支 | runningBranchs[原始仓库地址] |
| 单个/多个仓库 Tag | runningTags[原始仓库地址] |
| 分支模式 | branchModeBranchs，单独适配 |
| 运行变量 | envs[变量键] |
| 上游流水线制品 | runningPipelineArtifacts[流水线 ID] |
| ACR 制品 | runningAcrArtifacts[制品源键] |
| Packages 制品 | runningPackagesArtifacts[制品源键] |
| 运行备注 | comment |

用于项目匹配的归一化仓库地址不能替换提交时要求的原始键。相同源不能同时进入分支与 Tag 字典。params 外层为接口要求的 JSON 字符串，由编码器生成，避免手工双重转义错误。

## 6. 执行确认与运行状态

普通运行：参数 → 范围预览 → 确认运行。

生产运行：参数 → 明确列出「环境 + 主机/库/资源 + 具体动作 + 影响面」→ 用户勾选同意该完整范围并点击“确认发布到 …”。这是生产双重确认的第二阶段；最初点击运行和关注某条 Flow 都不等于授权发布。重试、取消、跳过、审批等生产变更也分别按本次动作确认，不复用旧许可。

预览有效期沿用现有 15 分钟，定义、参数、目标或代码/制品变化立即失效。确认绑定 connection/组织/pipeline/配置版本/代码源/环境/资源/参数摘要。秘密值不展示、不写日志，关联的摘要不包含可恢复凭据。

### 版本真实性

现有模拟适配器承诺固定 SHA，真实接入不能直接继承该承诺。CreatePipelineRun 当前公开参数按分支或 Tag 运行，分支预览 SHA 只是查询时的参考，提交前再查仍不能消除竞态。Tag 和版本名也不天然不可变。

建议首版对生产只开放已经验证不可变的制品/版本路径，或已证实支持精确提交且实际生效的调用；否则显示能力不足并暂停应用内生产提交。非生产按分支运行时清楚标注未锁定，运行后回填实际构建 SHA。这一限制需在实现评审中确认，不能在 UI 中伪装已锁定。

### 重复提交与失败

- 提交按钮立即进入忙碌状态；同一个本地确认预览只能提交一次。
- API 返回实例 ID 后，进入该实例详情并记录本地请求关联。
- 超时或断线后显示“提交结果未知”，不自动重试写请求；通过可获得的实例信息核对。不能仅凭备注或相近时间认定是自己的实例；无法唯一核对时转人工处理。
- 只读请求可退避重试；401 请求重连、403 解释权限、429 退避并保留缓存。
- 保留排队、运行中、等待人工、成功、失败、取消、未知；查询失败只改变同步状态，不覆盖云端最后已知状态。
- 运行实例保留当时的项目/环境/参数快照，后续修改映射不重写历史。

## 7. 授权交互

未连接页面显示“连接云效”，选择中心站 / Region 实例。

### 浏览器授权

按钮“使用浏览器授权”；展示登录中、用户取消、回调失败、登录成功等状态。采用系统浏览器、随机 state、PKCE S256、动态客户端注册与发现的端点；不用嵌入式网页登录表单。回调形式及重定向注册限制必须联调后确定，不能提前承诺自定义 URL Scheme 或随机本地端口必然可用。

说明文案：“授权后可访问该云效账号有权限的资源。工作台将按你的操作发起请求。”不将本地只读模式描述成 OAuth scope 权限。

访问与刷新令牌保存在 Keychain，刷新失败转重新授权；站点及账号改变后隔离缓存。断开连接清除本机凭据；官方未公开远端撤销端点，因此不承诺远端令牌同步失效。

### PAT

输入组织 ID（中心站）或实例地址（Region）及令牌；提供“测试连接”，显示实际验证的读取能力，运行权限不通过触发流水线来测试。可先配置只读 PAT，运行时提示缺少权限。

官方 CLI 明确文档化的是 PAT。OAuth 路径优先直接调用 OpenAPI，不能未经验证把 OAuth token 塞入 PAT 环境变量并声称受支持。两种方式共享 UI 和业务适配器，传输层分别验证。

## 8. 与现有工程的衔接

现有 `PipelineAdapter` 只有 listRuns/prepare/confirm，服务端模型主要保存本地模拟运行。实际接入要增加流水线目录，而不是把 PipelineRun 当成 Flow。

建议模型：

- YunxiaoConnection：站点、组织、账户、认证方式、凭据引用、能力状态。
- PipelineDefinition：远端稳定 ID、名称、代码源、配置版本、参数定义、同步状态。
- PipelineFavorite：连接/用户 + pipelineId；本地关注。
- PipelineBinding：source → project 多对多关系、环境规则、资源与确认信息。
- RunDraft / RunPreview：临时参数、保密值引用、预览范围和校验摘要。
- PipelineRun：真实实例 ID、当次范围快照、状态、阶段、实际代码/制品版本。

适配器增加 listPipelines/getPipeline/listRuns/getRun/getLogs、prepareRun/submitRun；传输层区分 PAT CLI 与 OAuth HTTP。UI 不拼 shell，应用不读取已有 CLI profile 或浏览器 Cookie。

本地写操作仍经 WorkbenchService；SQLite 做显式版本迁移和备份，保留任务库及工作区目录表。仅读取已有授权项目的 remote，不扫描其他 namespace。关注变化和映射编辑是本地操作。

刷新策略提案：列表手动刷新及低频后台同步，活跃实例 5–10 秒起步轮询，完成后降频；退避与取消请求，切换组织时取消上一组织任务。阶段/日志只在查看时加载。插件分页若不能暴露响应头，需要验证其自动分页能力或用 HTTP 适配器，不把首 30 条当全部。

## 9. 设计验收与实施顺序

第一阶段：连接、完整目录、本地关注、筛选、手动映射、详情和实例只读展示。

第二阶段：解析字符串/枚举/私密变量，多代码源与制品参数，非生产确认、提交、未知结果核对。

第三阶段：生产范围完整性、版本锁定能力与双重确认验证通过后，开放符合条件的生产运行；重试/取消/审批逐个动作设计。
