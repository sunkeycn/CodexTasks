# 可移植性与配置审计（2.2.1）

## 已改为每位用户独立配置

| 原先的假设 | 当前实现 |
| --- | --- |
| Codex 数据固定在 `~/.codex` | 默认解析 `CODEX_HOME`，回退当前用户目录；设置窗口可覆盖 |
| Codex／ChatGPT 固定安装在 `/Applications` | 通过系统 `codex://` 注册自动识别，支持手动选应用 |
| 固定每 60 秒补查、180 秒判断运行超时 | 设置中分别配置，保存立即生效 |
| 固定窗口切换快捷键 | 设置“窗口形态”中录制，默认 `⌘⇧空格`；保存即时注册，冲突保留原配置 |
| 旧 Hooks 命令指向构建包或源码脚本 | 新助手由完整应用包携带，安装到本地任务数据的稳定目录 |
| Hooks 依赖本机手动修改 JSON | 菜单栏设置中安装、更新、移除，合并保留其他 Hooks，先备份 |
| 任务数据依赖源码根目录 | 当前用户 Application Support 下独立 SQLite，支持 `--data-directory` |
| 构建依赖某台电脑的绝对路径 | 脚本从自身位置解析根目录，SwiftPM 无第三方包依赖 |

连接配置放在任务库旁的 `settings.json`，不进仓库。Hooks 在明确点击安装／移除时才写入所选 Codex 目录的 `hooks.json`；不编辑 `config.toml`、信任记录或聊天数据库。读取索引失败时仍可处理已获得的 Hooks 元数据。

## 有意保留的兼容性常量

- `ai.sunkey.floatingworkbench`：已发布应用的 bundle ID，保持已有用户偏好和应用身份。
- SQLite `application_id`、schema 5、字段和外键：已有任务数据库的兼容协议，不宜作为用户设置。
- `codex://threads/<UUID>`、Hooks 事件名和输入字段：与 Codex 集成的协议；私有索引和日志结构由适配器负责版本兼容。
- `Codex Tasks`、输出文件名、默认数据子目录：产品标识；无用户名、凭据、服务器地址或端口依赖。
- `⌘⇧空格`：可配置的窗口切换默认值，旧设置自动补齐；固定菜单快捷键与默认布局尺寸仍是产品交互默认值。侧栏宽度和折叠状态自动保留。
- 旧 `CodexStatusHook` 和旧项目脚本路径片段：仅用来识别、迁移本应用历史处理器，绝不会作为新安装的命令。
- 日志读取预算、JSON 大小限制及锁超时：资源保护边界，不是电脑相关配置。

## 本地文件与迁移

- `tasks.sqlite`：任务、Markdown 描述、父子关系、会话关联、所属项目名、排序及未读状态；备份使用 SQLite 备份接口。
- `settings.json`：当前电脑的连接配置与窗口切换快捷键（文件权限 0600）。
- `Integration/CodexTasksHook`：随当前版本安装的可执行助手；升级应用后可点击安装／更新重新部署。
- `Integration/events/<session UUID>.json`：执行状态与显式关联元数据；不保存正文、工作目录，不是聊天备份。
- `hooks.json.codex-tasks-backup-<UUID>`：修改前的原配置，保存在用户所选 Codex 目录中。

迁移步骤与 MIT 许可证说明见 README。应用和 ZIP 为本地 ad-hoc 签名，未加入开发者证书签名、公证或自动更新服务。仓库历史保留旧版本文档，历史文档可能含原开发机路径；当前构建不使用这些路径。应用包、ZIP、构建缓存和本地测试数据均已通过 `.gitignore` 排除。

## 验证边界

核心验收使用合成 Hooks 输入、临时 Codex 目录和任务库，覆盖合并配置、备份、重复安装／移除、异常配置不覆盖、路径转义、生命周期乱序、子代理过滤、超时，以及完成事件进入任务红点。测试不安装实际用户的 Hooks，不代替用户在 Codex 中信任，也不把合成回放当成真实客户端回调验证。
