# 悬浮开发工作台 · V1 产品规格

版本：1.0 · 2026-10-30

产品交互已由用户通过原型确认。本文件是后续实现的产品基线，覆盖此前 v0.1–v0.4 与 V1 候选稿中的冲突内容。技术选型属于实施建议，尚未经过真实接入验证。

本次确认只授权整理产品设计与开发任务，不授权连接真实资源、修改工具配置或发起部署。当前交付物是交互原型和规格，不是可安装的原生应用。

## 1. 产品定位与范围

一个苹果提醒事项风格的桌面悬浮开发工作台：记录任务，以任务号连接现有 Codex 会话，在同一入口查看项目、开发分支与 CI/CD。

已确认：

- 三个视角：任务、项目、CI/CD，共享任务与关联数据。
- 一个任务有稳定编号，可以关联多个项目、每个项目下的多个分支。
- 在现有 Codex 会话给出任务号后关联任务，自动同步执行状态。
- 任务只用圆形勾选框区分进行中和已完成；Codex 状态、流水线状态独立。
- Codex 额外发现先进入建议，用户采纳后成为正式任务。
- 云效通过现有 CLI 查询和部署，优先复用现有工具；Webhook 可作为已具备能力的适配方式。
- 默认快捷唤出，支持快速记录、自动置顶的待办小窗口和草稿保留。
- Codex 运行完成只更新角标；异常提醒，不抢焦点、不自动重试。

实施范围建议：macOS 首发、个人使用、数据保存在本机。产品名称、代码归属目录、技术栈与最低系统版本尚未锁定；跨平台、团队与云同步不作为首版实施前提。

## 2. 任务视角

### 2.1 列表和完成交互

每行主信息为左侧圆形勾选框、任务名，次级信息为任务号、关联项目/分支及 Codex 状态。悬浮窗口优先显示标题与编号，详情承载较长信息。

| 操作 | 结果 |
| --- | --- |
| 新建任务 | 自动分配稳定编号，未勾选，进行中 |
| 点击空圆圈 | 已完成，标题减淡并加删除线 |
| 点击已勾选圆圈 | 恢复进行中 |
| 点击任务名 | 打开任务详情，不改变勾选 |
| Codex 运行结束 | 只更新执行记录和角标 |
| 流水线结束 | 只更新流水线记录 |

人工任务状态严格只有进行中、已完成。不增加待办、待验收、挂起、关闭。任务完成后保留原位，方便直接取消；自动移出和自动归档不纳入首版默认行为。列表与详情的勾选始终一致，支持键盘空格切换。

人工勾选不取消正在运行的 Codex。已完成但仍有执行时照常展示“Codex 正在运行”。停止执行仍在原 Codex 会话操作。

### 2.2 详情

包括任务号、标题、说明、完成标准、勾选状态、按项目分组的分支关联、默认入口、Codex 执行历史与结果、相关流水线、后续建议。

任务允许暂不关联项目，快速记录时不强制填写说明、分支或完成标准。任务号不可编辑、不复用；标题与项目改名不影响编号。

### 2.3 多项目与分支

- 当前会话已处于任务关联项目时，优先该项目。
- 同项目多个关联分支时，使用明确设置的项目内默认分支；没有唯一结果时要求选择。
- 没有项目上下文时使用任务的默认入口；无默认或入口失效时要求选择。
- 默认入口只帮助定位，不构成目录访问授权，也不启动全部关联项目。
- 关联任务不会静默切换 Git 分支。当前分支不符时展示差异，不能把关联动作等同于 checkout。
- 解除关联保留实际分支、仓库及执行历史，提供撤销；解除默认关联后清空默认入口。
- 已开始的执行保存当时范围；后续修改任务关联不改变历史范围。

## 3. 项目视角

项目列表展示项目名、我的活跃分支数量、进行中任务数及最近流水线摘要。项目详情以“我关注的开发分支”为主列表，显示关联任务与最近执行/流水线结果。

“关注分支”与“关联任务”分开：取消关注不解除关联；解除关联不取消关注。分支可以暂时没有任务，也可以关联多个任务。

从分支可以关联已有任务，或新建任务并自动带入当前项目和分支。其他可见分支可手动加入关注列表。提交作者仅可作为发现线索，不能直接判定“这是我的分支”。

只展示用户登记并授权的项目。保留仓库身份、分支 ref 与 checkout/worktree 路径之间的区别。分支已删除或暂时无法读取时保留历史关联并标明状态；读取失败不能当成分支删除。

## 4. Codex 联动与状态

### 4.1 日常闭环

1. 用户在工作台记录任务，得到例如 `T-128`。
2. 在已有 Codex 会话提供该编号，已安装的联动工具精确查询任务。
3. 返回允许范围内的说明、验收要求和项目/分支关联，建立会话与任务关系。
4. 执行开始后显示正在运行；执行结束后显示运行完成及摘要。
5. 用户检查结果，用圆圈勾选完成；需要继续时保持或恢复进行中。

首次接入需要安装并配置工具及工作规则；“只给任务号”是配置后的体验目标。普通数字不默认解释成任务号。任务关联本身只定位上下文，具体工作仍服从该次用户指令。

### 4.2 会话、执行和任务分别记录

一个任务可有多个会话，每个会话可有多次执行；一次执行保存不可变的任务与项目范围快照。会话后续切换任务，不迁移之前的执行。

| 对象 | 对用户显示 | 变化来源 |
| --- | --- | --- |
| 任务 | 进行中、已完成 | 用户勾选/取消勾选 |
| Codex 执行 | 正在运行、运行完成；需要输入、失败、中断、同步未知按异常单独显示 | 可信生命周期事件或明确标识的降级回写 |
| 流水线 | 排队、运行、待审批、成功、失败、取消、未知 | 云效运行实例 |

没有执行记录时显示尚未运行；一个执行结束不能掩盖其他正在运行的执行，可显示“正在运行 2 项”。执行结束不代表任务验收通过，流水线成功也不能单独证明服务已健康上线。

已完成任务仍允许查看和关联上下文，不自动取消勾选。若用户明确要求继续工作，可记录新的执行，同时提示任务当前已完成，由用户自行决定是否取消勾选。

### 4.3 自动维护的边界

允许 Codex 查询和关联任务、报告执行、提出新增事项建议；人工勾选字段不开放给自动事件修改。采纳建议只创建任务，不自动启动执行。

失联和超时显示未知及最后同步时间，不能推断为完成。运行完成通知以执行实例去重。同步恢复后按事件标识与序号处理重复、迟到事件，避免回退已知状态。

**技术验证关口：**现有 Codex 桌面会话是否提供本应用可订阅的可靠起止/异常事件，尚未验证。自定义 MCP 工具是拟建接口，不代表现成能力；模型主动调用结束工具也不能覆盖崩溃、取消和强制退出。必须先完成接入验证，不能在上线时用猜测补齐状态。

如果只能做到主动回写，界面须标记其来源并在失联时降级未知；这只能算阶段成果，不能视为可靠自动同步已验收。另开受本工具管理的执行通道不能擅自替代“沿用现有 Codex 会话”的已确认要求。

## 5. CI/CD 与部署

按项目和环境查看运行实例，显示流水线、分支、提交、阶段、结果、关联任务、最后同步时间和可用的日志入口。数据过期或离线时保留最后结果并标记过期。

部署流程：选择单个项目与分支 → 选择环境 → 生成预览 → 确认具体范围 → 触发一次 → 跟踪运行实例。

预览必须包含项目、环境、主机/资源、动作、影响面、分支、提交 SHA、流水线与参数，以及可选关联任务。一个任务关联多个项目不代表批量部署。

确认绑定预览快照。分支提交或任一执行参数变化，原预览失效；服务在触发前复核，不能只依赖前端按钮。云效适配器必须验证能锁定对应提交：如果 CLI 只能按可变分支启动且无法保证实际提交，暂不开放这条部署路径，不能用“刚检查过 SHA”充当版本锁定。

触发超时标记提交结果未知，优先用远端实例核对；禁止盲目重试造成重复发布。部署状态更新不能改变任务勾选。

除 dev/test/daily/pre 外均按生产处理。生产写操作先展示“环境 + 主机/库/资源 + 具体动作 + 影响面”，再取得针对本次范围的明确确认；设计确认、以前的部署确认或任务完成均不可代替。生产只读先声明目标环境；不确定时按生产处理并先确认。此规则也约束自动轮询的首次接入范围。

## 6. 窗口、快速记录和提醒

2026-11-02 UI 更新：标题位于左侧工作区选择器上方，删除「工作区 · WorkSpace」标签；原生标题栏只保留右侧缩小操作，移除自定义提醒、关闭与钉住按钮。系统左上角关闭保留隐藏行为。

| 场景 | 已确认默认行为 |
| --- | --- |
| 日常入口 | 快捷唤出；恢复上次视角 |
| 大窗口点击其他应用 | 普通窗口层级，保持可见；允许被其他窗口正常遮挡 |
| 待办小窗口点击其他应用 | 自动置顶，保持可见；不提供手动钉住按钮 |
| 点击关闭 | 隐藏窗口，保留后台服务 |
| 缩小为待办卡片 | 提醒事项风格圆角卡片，显示当前工作区待办或正在运行的事项，运行优先；可勾选完成、打开详情和展开 |
| 快速记录 | 直接聚焦输入；Enter 新建；不启动 Codex |
| Codex 完成 | 更新状态与角标，不弹窗、不抢焦点 |
| 异常或需要处理 | 提醒一次，点击定位任务/流水线 |

忽略提醒不删除记录；同一事件不能重复弹出。完成提醒和异常提醒可分别设置。真正退出与隐藏不同：退出若停止同步须明确展示影响，不能宣称仍在同步。

全局快捷键具体组合、最低系统版本、多显示器/全屏空间、休眠恢复和原生通知权限均属实现验证项；先前原型按钮只模拟行为。窗口尺寸采用可调整方案，默认宽度待原生实测，不把不同原型中的像素值视为最终尺寸。

## 7. 实施架构建议

建议 macOS 界面采用 SwiftUI + AppKit，本地 SQLite 保存数据；设单一 Workbench Service 作为所有写入入口。架构方向服务于当前交互，尚不构成已确认技术选型或依赖版本。

```text
悬浮窗口 / 菜单栏 / 原生通知
             │
       Workbench Service ── SQLite
        ├─ Codex Bridge：任务工具 + 生命周期适配
        ├─ Git Adapter：已登记仓库与分支
        └─ 云效 Adapter：CLI 查询、部署、结果映射
```

服务负责编号分配、关联、幂等事件、状态汇总与部署计划。界面与适配器不各自直接修改数据库。隐藏窗口不销毁服务；退出、重启、迁移与恢复的行为需独立验证。首版不需要云端服务。

### 7.1 最小数据模型

| 实体 | 核心字段/约束 |
| --- | --- |
| Task | UUID、唯一稳定编号、标题、说明、完成标准、is_done、completed_at、version；只有用户操作可改 is_done |
| Project / Repository / Checkout | 项目身份、仓库身份、明确授权的真实路径；worktree 不充当仓库身份 |
| Branch / BranchFollow | 仓库 + ref、最近确认 SHA、可用状态；关注关系独立保存 |
| TaskProject / TaskBranch | 多对多关联、可空的默认入口；分支必须属于已关联项目 |
| SessionAttachment | 外部会话标识、当前任务、上下文来源与版本 |
| CodexRun | 外部会话/turn 或适配器执行标识、任务和范围快照、状态、来源、序号、同步时间、结果摘要 |
| Suggestion | 来源任务/执行、建议、理由、采纳或忽略结果；采纳幂等 |
| PipelineBinding / PipelineRun | 项目、环境、远端流水线/实例标识、提交、参数、阶段、结果、同步时间 |
| DeploymentPlan | 完整范围快照、预览摘要、确认与失效状态、触发结果；复用确认不可重复触发 |
| Event / Notification | 事件来源和幂等标识、对象版本、时间、操作记录；提醒去重和已读状态 |

### 7.2 自定义接口草案

以下是将要开发的协议名，不是 Codex 内置工具：

- `task.resolve(number, context)`：精确查询，按授权范围返回上下文。
- `task.attach(number, session, context)`：关联会话，不切分支、不启动任务。
- `task.report_run(run, event)`：记录执行事件，不能修改人工勾选。
- `task.propose_followup(task, suggestion)`：写入建议。
- `task.set_completed(task, value, expected_version)`：只供用户界面使用，设置明确值，避免重试把 toggle 翻回去。
- `project.list_branches(project)`：已登记项目分支及独立关注状态。
- `cicd.list_runs(binding)`、`cicd.prepare_deployment(scope)`：查询与预览。
- `cicd.confirm_and_start(plan, confirmation)`：核对预览、授权与一次性执行；服务端保留结果供重复请求查询。

本地连接仍需校验调用者与授权范围；任务关联不等于跨工作区代码授权。凭据复用现有安全存储，不写入任务库或日志。CLI 使用参数数组，任务标题/分支等不得拼接为可执行 shell 字符串。

## 8. 可行性结论与交付关口

产品模型可按本地应用实施。交互原型已演示圆圈勾选、执行状态分离、关联关系、部署预览失效和窗口行为；尚无原生系统或真实服务验收证据。

| 部分 | 当前结论 | 上线前证据 |
| --- | --- | --- |
| 任务与关联 | 规则已明确，可独立实现 | 编号持久化、勾选一致、多项目与恢复测试 |
| 原生悬浮 | 实施方案待实机验证 | 置顶/隐藏、焦点、快捷键、休眠与多屏检查 |
| 现有 Codex 同步 | 最大接入不确定项 | 真实会话正常、异常、并发、重启事件证据 |
| 云效状态查询 | 需验证用户实际 CLI 契约 | 明确命令/版本、脱敏输出和实例映射 |
| 云效部署 | 依赖提交锁定、授权及结果核对 | 指定开发/测试环境一次完整闭环 |

公开文档检索未获得本轮可用结果，未据此新增当前 API 能力保证。先前 CLI/协议探查只作为验证线索；不能证明现有桌面会话开放完整事件订阅。具体技术能力以开发阶段的受控接入证据为准。

首版暂缓团队协作、多设备同步、自动排期、隐式批量部署、全量历史会话导入、苹果提醒事项双向同步和系统桌面 Widget。完成隐藏/归档策略可在真实使用后再迭代。

## 9. 验收基线

1. 重启、改名、完成与重新打开均不改变任务号，编号并发分配不冲突、不复用。
2. 勾选完成、取消恢复进行中；列表与详情一致，任务完成后可直接取消。
3. 多会话、多次执行、流水线和迟到事件均不覆盖人工勾选。
4. 当前项目优先、默认入口回退与歧义处理正确，不自动切分支或扩大目录范围。
5. 关注/关联独立；解除可撤销，历史范围不随关联变化而改写。
6. 异常退出/断联不冒充完成；同步来源和最后更新时间可见。
7. 部署按单项目执行，预览绑定实际提交；范围变化使确认失效，重复请求不重复部署。
8. 隐藏/收条保留后台工作与草稿，真实退出或服务失联有明确状态。
9. 正常完成安静更新，异常去重提醒，可定位对应记录。
10. 所有接入遵守明确工作区范围及逐次生产确认规则。

开发顺序、任务依赖和验证场景见同目录《悬浮开发工作台-V1开发任务拆分.md》。
